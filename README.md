# Rosie Reel Maker

iPhoneのSafariで写真を並べてリールをプレビューする、React + TypeScript + Vite製の試作品です。

## 起動

Node.js 22.12以降（または20.19以降）が必要です。

```sh
npm ci
npm run dev
```

写真の編集・プレビューは開発PCと同じネットワークのiPhoneから、表示されたNetwork URLにアクセスして確認できます。MP4書き出しにはHTTPS（開発PC自身ではlocalhostも可）が必要です。iPhoneではGitHub Pages等のHTTPSで確認してください。静的ホスティングでは `npm run build` が生成する `dist/` を配信します。アプリ用バックエンドは不要です。

```sh
npm test
npm run build
npm run preview
```

## 使い方

1. 「写真を追加する」で複数の写真を選びます。
2. 「前へ」「後へ」で順番を変えます。
3. 各写真の表示秒数を0.5〜60秒、小数1桁までで設定します（初期値1.5秒）。
4. 「再生する」で9:16のプレビューを確認します。一時停止・再開・先頭への復帰に対応しています。

写真は中央を基準に画面いっぱいに切り抜きます。編集時は先頭に戻り、最後まで再生すると停止します。別タブへの移動・画面ロック時は一時停止します。

## データと制限

- 写真はObject URLで端末内に保持し、外部送信しません。外部フォント・解析サービスも使用しません。
- 再読み込み・ページを閉じると写真と編集内容は失われます。
- Safariでデコードできる画像が対象です。HEICなどはOS・ブラウザの対応状況に依存し、失敗した場合は案内を表示します。
- 写真の削除・アプリの破棄時にObject URLを解放します。大量の高解像度写真は端末のメモリ制約を受けます。
- 動画素材・音声・Instagramへの投稿・下書き保存は未対応です。MP4書き出しは対応端末で利用できます。

## 検証

`npm test` は秒数境界、並べ替え、秒数入力、複数取り込み、再生・停止・再開、削除と読み込み失敗時のURL解放を検証します。画像デコードとアニメーションフレームはテスト用に置き換えています。

iPhone実機での確認項目：写真ライブラリからの複数選択、HEIC/JPEGの表示、タッチでの並べ替え、秒数入力、画面ロックからの復帰、縦横回転、9:16表示。自動テストは実機検証の代わりにはなりません。

## GitHub Pagesで公開する

公開リポジトリのGitHub Pagesと標準のGitHubホストランナーを使用するため、この構成は無料で利用できます。独自サーバー・有料サービス・デプロイ用の個人アクセストークンは不要です。

### GitHub側で初回に行う操作

1. リポジトリの **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選択します。
2. **Actions** が無効な場合は有効にします。組織等で制限がある場合は、このワークフローで使用する公式Actionsを許可します。
3. プルリクエスト #1の変更と **Build and test** の成功を確認し、公開してよいと判断した時点で自分でmainへマージします。PRへのpushだけでは公開されません。
4. **Actions → Deploy to GitHub Pages** のbuildとdeployが成功するまで待ちます。環境の承認が表示された場合は内容を確認して承認します。
5. Settings → Pagesの公開URL、またはデプロイのenvironmentリンクを開きます。

公開成功後にiPhoneのSafariで開くURL：

https://kotarrows629.github.io/rosie-reel-maker/

このURLは公開先の予定URLです。初回デプロイが完了するまでは404になる場合があります。

以後mainへのpushでテスト・ビルド後に自動デプロイされます。必要なら **Actions → Deploy to GitHub Pages → Run workflow → Branch: main** で再実行できます。手動実行でもmain以外のブランチは公開しません。失敗した場合はActionsの赤くなったステップを確認してください。

Viteの `base` は `/rosie-reel-maker/` に固定しています。開発サーバー・`npm run preview` でもこのパスを開いてください。リポジトリ名や公開パスを変える場合は `vite.config.ts` のbaseも変更します。

公開するのはビルド済みのアプリだけです。選択した写真はGitHub Pages・GitHub Actionsを含むサーバーへ送信せず、引き続きブラウザ内だけで扱います。動画素材の選択は未対応です。


## MP4書き出し（第2段階・実験的）

1. 写真の順序・秒数を設定し、「動画を保存」の画質を選びます。
2. 「動画を保存」をタップし、この画面を開いたまま完了を待ちます。
3. 「共有・写真に保存」が使える場合は共有メニューから「ビデオを保存」を選びます。表示されない場合は「ファイルに保存」または「MP4をダウンロード」を使い、ファイルアプリから共有します。

- 1080×1920または720×1280、30fps、H.264のMP4（音声なし）。プレビューと同じ中央基準の切り抜きです。
- WebCodecs/H.264対応を端末ごと・画質ごとに確認します。非対応の端末でも編集とプレビューは利用できます。能力チェックは成功を保証しないため、生成失敗時は軽量画質で再試行してください。
- 初期値は1.5秒。書き出し時は30枚・60秒以内に制限します。順番・秒数を変更すると生成済み動画は破棄され、再書き出しが必要です。
- フレームは1枚ずつエンコード待ちし、写真の追加デコードも1枚ずつ行います。処理中は写真編集をロックします。画面非表示・ページ離脱・中止ボタンで書き出しを中止し、各非同期処理には30秒の待ち時間上限を設けています。
- 元画像と最終MP4はメモリに残るため、端末のメモリ不足を完全には防げません。大量の高解像度写真ではOSがページを終了する場合があります。短い動画・軽量画質でお試しください。
- 写真アプリへの無断の直接保存はできません。共有・保存にはユーザーの操作が必要です。Instagramへの取り込みはiPhone実機で確認してください。
- 写真・動画は外部送信しません。エンコード・MP4の組み立て・保存用ファイル生成は全てブラウザ内で完結します。無料のMediabunnyライブラリを同梱し、外部CDNからの取得も不要です。

技術調査・検証範囲と代替案は [docs/mp4-feasibility.md](docs/mp4-feasibility.md) を参照してください。iPhone実機Safariは未検証です。
